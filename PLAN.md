# PLAN: Pediatric Moonshot Interactive Atlas Platform

## Context

BevelCloud is building a web platform to present the Pediatric Moonshot disease atlases and AI diagnostic agents to Timothy Chou (Founder, PediatricMoonshot.org). The platform has two core experiences:

- **Atlas Explorer** — search and browse all 617 conditions across 4 specialties (Cancer, Cardiology, Nephrology, Neurology), with clean per-condition disease pages
- **AI Agent Questionnaire** — for conditions with agent files, an interactive 100-point diagnostic scoring questionnaire that filters questions by tests completed, shows live scoring, and ranks pending tests by points-per-dollar

**#1 requirement:** all information must be represented exactly as it appears in the source files — no reinterpretation, no summarizing. Every field displayed is the raw text from the atlas or agent, formatted for legibility.

---

## Critical Findings from Exploration

### Agent Data (xlsx) — Two Distinct Schemas

**Cardiology & Kidney agents (21 sheets): Full 100-point scored framework**
- 5 columns: Domain | Question | Confirming Answer | Points | Cost (Small/Medium/Large)
- Section headers mark domain subtotals (e.g., "ECHOCARDIOGRAPHIC / IMAGING — 45 pts")
- 3 confidence rows at end (🔴🟡🟢)
- Non-standard totals in 4 Kidney agents: IgAN = 143 pts, aHUS = 88 pts, APOL1 = 79 pts, C3G = 63 pts → scoring normalizes to percentage, not 100-point assumption
- Confidence thresholds vary: most use ≥80/50-79/<50; aHUS/APOL1/C3G use ≥80/60-79/<60

**Neurology agents (9 sheets): Diagnostic checklist format**
- Only Columns 1-2 used (Domain + Question); no Points, no Cost, no scoring
- 65–89 rows of questions per sheet
- Presented as "Diagnostic Checklist" in UI — no live scoring or points-per-dollar (honest to the data)

### Atlas Data (PDF)
- Cancer: 104 conditions, 11 categories, 23 pages
- Cardiology: 104 conditions, 11 categories, 59 pages
- Nephrology: 176 conditions, 17 confirmed categories, 98 pages — richest clinical detail with SOC/Emerging color-coding
- Neurology: 233 conditions, 15 categories, 68 pages — VERIFIED notations, hereditary tiers
- All 4 atlases share: hereditary tier emoji (🧬🧬🧬 Strong | 🧬🧬 Dominant | 🧬 Associated | none), US + Global frequency, SOC vs. Emerging treatment

## Tech Stack

| Layer | Choice | Reason |
|-------|--------|--------|
| Framework | Next.js 14 (App Router) | Industry standard; file-based routing maps cleanly to specialty/condition structure; SSG for fast page loads |
| Language | TypeScript | Type safety is essential for complex scoring logic and atlas data schemas |
| Styling | Tailwind CSS | Rapid, consistent, utility-first — right for a complex data-heavy UI |
| Search | Fuse.js | Client-side fuzzy search over 617 conditions — no backend needed |
| Deployment | Vercel | Free tier, zero-config Next.js deployment, instant |
| Icons | Lucide React | Clean, consistent icon set |
| Data | Static JSON files (in src/data/) generated by Python parse scripts | Accuracy-first: raw text stored verbatim from source files |

## TypeScript Interfaces (lib/types.ts)

```typescript
type Specialty = 'cancer' | 'cardiology' | 'nephrology' | 'neurology'
type HeredityTier = 'strong' | 'dominant' | 'associated' | 'none'

interface AtlasCondition {
  id: number
  slug: string
  specialty: Specialty
  category: string
  name: string
  heredityTier: HeredityTier
  description: string
  frequency: { us: string; global: string; sources?: string }
  diagnosis: string
  treatment: { standardOfCare: string; emerging: string }
  hasAgent: boolean
  agentSlug?: string
}

type CostTier = 'Small' | 'Medium' | 'Large'

interface AgentQuestion {
  domain: string
  question: string
  confirmingAnswer: string
  points: number
  cost: CostTier
}

interface AgentSection {
  heading: string
  sectionPoints: number
  questions: AgentQuestion[]
}

interface ScoredAgent {
  type: 'scored'
  conditionId: number
  conditionName: string
  specialty: Specialty
  agentType: 'diagnosis' | 'progression'
  totalPoints: number
  preamble: string
  sections: AgentSection[]
  confidenceThresholds: {
    high: { min: number; label: string; action: string }
    moderate: { min: number; label: string; action: string }
    low: { max: number; label: string; action: string }
  }
  guidelinesCitation?: string
}

interface ChecklistQuestion {
  domain: string
  question: string
}

interface ChecklistAgent {
  type: 'checklist'
  conditionId: number
  conditionName: string
  specialty: 'neurology'
  agentType: 'diagnosis'
  sections: Array<{ heading: string; questions: ChecklistQuestion[] }>
}

type Agent = ScoredAgent | ChecklistAgent

interface ScoringState {
  completedTests: Set<string>
  answers: Record<string, boolean | null>
}

interface ScoreResult {
  currentScore: number
  maxAchievable: number
  totalPoints: number
  pendingTests: PendingTestResult[]
}

interface PendingTestResult {
  testId: string
  testLabel: string
  costTier: CostTier
  estimatedCost: number
  potentialPoints: number
  pointsPerDollar: number
}
```

## Scoring Logic (lib/scoring.ts)

### Test Selection → Question Filtering

| Domain + Cost | Test Label |
|---------------|------------|
| Any + Small | Pre-checked (standard clinical encounter) |
| Genetics + Medium | "Genetic Panel Testing" |
| Cardiac MRI + Large | "Cardiac MRI" |
| Echo/Imaging + Large | "CT / MRI Angiography" |
| RHC + Large | "Right Heart Catheterization" |
| Exercise/Stress + Medium | "Exercise Stress Testing" |
| Biomarkers + Medium | "Advanced Biomarker Panel" |

Small-cost items are pre-checked by default. Medium and Large are unchecked — user opts in.

### Question Eligibility
```
isEligible(question, completedTests) →
  question.cost === 'Small'
  OR question.cost === 'Medium' AND testSelected(question.domain, 'Medium')
  OR question.cost === 'Large' AND testSelected(question.domain, 'Large')
```

### Live Score
```
currentScore = sum(points for all 'yes' answers among eligible questions)
maxAchievable = currentScore + sum(points for all unanswered eligible questions)
```

### Points-per-Dollar (results page)
```
potentialPoints = sum(points for all questions gated behind this test)
estimatedCost = { Small: 100, Medium: 850, Large: 3250 }[cost]
pointsPerDollar = potentialPoints / estimatedCost
```
Rank descending by pointsPerDollar.

### Confidence Output
Normalize to percentage for non-100-point agents (IgAN=143, aHUS=88, APOL1=79, C3G=63):
`score / totalPoints * 100` then compare against agent-specific thresholds.

## Key UI Flows

### Home Page (/)
- Hero tagline from atlases
- Global search bar (Fuse.js across all 617 conditions)
- 4 specialty cards with condition counts
- Small mission context section linking to pediatricmoonshot.com and bevelcloud.ai

### Specialty Page (/[specialty])
- Sidebar: category filter
- Main: scrollable condition list with name, heredity badge, category, 1-line description
- Search input (within specialty)
- "Has Agent" filter badge

### Disease Detail Page (/[specialty]/[slug])
- Condition name + heredity badge
- Description | Frequency (US + Global) | Diagnosis | Treatment
- Treatment split: Standard of Care (blue) | Emerging/Investigational (amber)
- If hasAgent: prominent "Run Diagnostic Agent →" button
- Source field: which atlas + condition number

### Agent Questionnaire (/[specialty]/[slug]/agent)

**Scored Agents (Cardiology / Kidney):**

Step 1 — Test Selection:
- "What testing has been completed for this patient?"
- Pre-checked: all Small-cost categories
- Checkboxes for Medium + Large tests
- Preamble text from agent displayed as context
- "Begin Assessment →" button

Step 2 — Questions:
- Sectioned by domain
- Only eligible questions shown
- Yes / No / Skip toggle per question
- Sticky Live Score Widget: current score, max achievable, confidence indicator (🔴🟡🟢), progress bar

Step 3 — Results Panel:
- Confidence verdict + interpretation text
- Scores: Current | Max Achievable Now | Full Maximum
- Pending Tests table ranked by points-per-dollar
- Guidelines citation (for progression agents)

**Checklist Agents (Neurology):**
- No test selection step
- Questions shown by domain with checkboxes
- No live score — "X / Y items checked" counter
- Results: summary of checked items by domain
- Label: "Diagnostic Checklist" (not "Scored Agent")
